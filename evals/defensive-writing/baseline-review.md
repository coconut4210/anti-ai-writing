# 防御性写作基线记录

规则版本：无 `03-防御性写作.txt`。

| 案例 | 是否触发预期失败 | 证据片段 | 备注 |
|---|---|---|---|
| DW-B01 | 是 | “它不是只会问答的聊天机器人，而是……” | 用户把“普通聊天机器人”作为排除约束，正文仍复述并反驳该对象。 |
| DW-B02 | 边界样本 | “并非因为免费的东西真的标价最高，而是……” | 否定结构承担对修辞命题的概念界定，不能仅凭句式判错；但后文出现若干未经材料支持的普遍化表述。 |
| DW-B03 | 否 | “这套课程着重训练学生的问题拆解能力……” | 正确删除排除对象及其附属免责声明，是需要保护的正例。 |
| DW-B04 | 否 | “‘代码公开’并不等于‘安全性降低’。” | 用户明确要求反驳，必须允许保留真实对立对象和必要限定。 |
| DW-B05 | 部分触发 | “有助于提升工单流转效率……”随后才声明没有测试数据 | 在无数据时先断言价值，再以免责声明回撤；能够指出待验证指标，但没有按第四检查器形成逐项授权选项。 |

## 基线结论

1. `constraint_leakage` 已出现明确失败样本，规则需要阻止把用户排除项改写成正文反驳。
2. 否定结构既可能是失败，也可能承担必要定义或用户要求的反驳，不能按关键词删除。
3. 模型能够在强指令下剪除防御链，因此规则应提供正向输出契约，而不只列禁令。
4. 证据不足时容易出现“先断言、后免责声明”的结构；第四检查器需要在完整成稿后把缺口转成可操作的逐项决定。
