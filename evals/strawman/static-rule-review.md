# 稻草人规则静态试跑报告

## 范围

本次仅检查现有规则能否区分预先构造的失败片段和允许片段。它验证的是规则定义与样本边界，不验证尚未实现的 Skill 是否能稳定生成合格文章。

## 结果

| 用例 | 预期 | 规则判定 | 依据 |
|---|---|---|---|
| ST-RULE-001-F | 失败 | 失败 | 将“项目更有效”加强为“教程毫无价值”后反驳。 |
| ST-RULE-001-P | 通过 | 通过 | 讨论教程的功能，但没有归给用户“教程无用”的立场。 |
| ST-RULE-002-F | 失败 | 失败 | 将“优先”改造成“只能”。 |
| ST-RULE-002-P | 通过 | 通过 | 外部异议的来源明确，且直接回应优先级问题。 |
| ST-RULE-003-F | 失败 | 失败 | 删除早期阶段与需求变化条件。 |
| ST-RULE-003-P | 通过 | 通过 | 保留条件并说明条件改变后的结论变化。 |
| ST-RULE-004-F | 失败 | 失败 | 将概率风险改造成必然作弊。 |
| ST-RULE-004-P | 通过 | 通过 | 保留概率表述并分析决定变量。 |

静态用例共 12 条，规则判定与预期一致 12 条。该结果只能说明规则能够表达这些人工构造的边界，不能据此声称规则在真实创作中准确率为 100%。

## 当前发现

1. “不是说”“不意味着”“不能因为”等句式是高风险线索，但不能单独作为判定依据；必须检查其后的命题是否由用户原论点蕴含。
2. 合理异议与稻草人的关键差别不是观点是否强烈，而是异议是否被错误归给用户。
3. 条件分析、最低约束和承认其他价值都可以保留，只要没有把它们包装成对用户的纠正。
4. 规则必须以局部片段判定问题，同时用全文占比确定严重程度。
