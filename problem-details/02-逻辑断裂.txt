
# 逻辑断裂

状态：候选规则 V1；已完成 4 例初步基线/对照测试与一次隔离审计，完整测试矩阵和人工盲审仍待完成。

## 1. 定义

逻辑断裂包含两个相互独立、需要分别检查的维度。

### 1.1 关系断裂（Logical Validity）

文本将命题 A 与命题 B 表达为存在因果、推论、解释、证明或意义对应关系，但已有信息不足以支持该关系。两个命题各自可能合理，连接却依赖未说明、未经验证或循环论证的前提 W。

- 有效连接：A 与 B 的关系类型明确，现有依据足以支持当前强度的结论。
- 无效连接：只因语义相近、意象相似、时间相邻或主题相关，就将 A 写成 B 的原因、依据或必然结果。
- 典型表现：相关性写成因果性、可能性写成必然性、解释假设写成事实、多级推论依赖未经验证的中间结论。

### 1.2 推进断裂（Argumentative Progression）

新增内容与主题相关，甚至命题关系本身合理，但没有增加有效证据、解释机制、推论、限定或必要整合，文章因此不断铺陈而没有推进核心论点。

主题相关度高、新增字数多、案例数量增加或表达更具体，都不能单独证明论证得到推进。

### 1.3 非目标与排除条件

- 不把语言不流畅、句子长短或连接词偏好直接判为逻辑断裂。
- 不要求每句话都产生新结论；定义、必要背景、铺垫、例子、过渡和审美表达可以承担合法功能。
- 不把文学、评论或个人感想强行改造成学术论文。
- 主观联想只要归属明确、有可理解的观察基础，并且没有伪装成客观因果，就可以保留。
- 检查粒度默认以段落或论证单元为主，只在关键推论处细化到命题。

## 2. 用户核心论点保护

用户要求文章探讨、表达或发展的核心论点标记为 `user_position`，与模型新增的支持理由、解释、假设和外部事实分开处理。

1. `user_position` 是本次创作需要忠实发展的目标，不得因为用户没有同时提供完整证据，就由 Validator 擅自删除、反驳或替换成另一立场。
2. 逻辑检查首先约束模型新增的 `generated_support`、`interpretation`、`hypothesis` 和它们与核心论点之间的连接。
3. 如果用户核心论点本身包含强事实、因果或普遍化判断，可以在不改变立场的前提下明确其条件、范围或观点属性；不能在内部修复时悄悄改弱成另一篇文章。
4. 只有当歧义会实质改变核心论点、论证对象或结论方向时，才向用户提出一个关键问题；其他情况下采用保守解释继续创作。
5. 用户明确要求保护的表述、事实和价值判断优先于默认优化策略。

内部命题可标记为：

```text
user_position
observed_fact
sourced_fact
generated_support
interpretation
hypothesis
value_premise
```

## 3. 总体流程

```text
用户论点与材料
      ↓
生成前规划：命题关系 + 论证目标
      ↓
受控创作：Claim Gate + Progression Gate
      ↓
成稿复核：Validity Audit + Progress Audit
      ↓
局部修复 → 双重复验 → 最终正文
```

以上结构属于内部工作流，不是终稿格式。如果运行环境支持多次独立调用，Validator 应只读取原始任务和实际正文，重新抽取命题与段落功能；如果只能单次调用，只能称为成稿复核，不能宣称是完全独立验证。

## 4. 生成前规划

### 4.1 提取输入约束

确认：

- `thesis`：用户核心论点；
- `task`：用户希望完成的文章类型；
- `audience`：目标读者；
- `genre`：分析、评论、说明、叙事或其他；
- `context`：已知事实、素材、用户观点及允许引用的来源；
- `argument_scope`：文章准备讨论到什么范围；
- `constraints`：篇幅、风格和不可修改内容。

### 4.2 建立命题关系计划

1. 列出少量关键命题，不为所有句子建立关系图。
2. 仅为存在推导意图的命题添加关系边：

```text
causal
inferential
explanatory
evidential
analogical
interpretive
```

3. 每条关键边指出支持机制、条件或依据 W；同义改写、比喻和连接词本身不能充当 W。
4. 标记支持状态：

```text
supported
plausible_but_unverified
unsupported
contradicted
```

5. `unsupported` 与 `contradicted` 关系不得规划成确定性结论；不确定关系应被限定、改写为假设、重新连接或移除。
6. 不因 A 与 B 属于同一主题就建立 A→B，不把相关性直接写成因果性。
7. 结论强度、范围和确定性不得超过其依据。

### 4.3 建立论证推进计划

将核心论点拆成少量 `argument_goals`。每个目标记录：

```text
goal_id
question_to_answer
required_support
completion_criteria
dependencies
```

目标不是章节标题，而是内部需要解决的问题，例如：

- 文章具体讨论什么对象？
- 这一现象通过什么机制发生？
- 哪些事实、观察或案例能够支持？
- 结论在哪些条件下成立？
- 已有内容能够推出什么阶段性判断？

对评论和主观写作可以设置 `interpretive` 目标，其标准是“明确观察 + 有边界的解释”，不强制要求实证证明。

## 5. 推进贡献分类

一个段落或关键命题可以通过以下方式推进论证：

| 类型 | 判断要求 |
|---|---|
| `evidence_increment` | 增加能够支持某个待证明命题的事实、材料或非重复案例，并能说明支持对象 |
| `mechanism_increment` | 补足为什么或如何发生，而不是换词重述现象 |
| `inference_increment` | 在已有前提上形成有依据的新结论 |
| `boundary_increment` | 明确成立条件、适用范围、反例或重要限制 |
| `synthesis_increment` | 将已有材料整合成此前没有得到的解释或判断 |

允许的非直接推进状态：

- `necessary_context`：必要背景或铺垫，必须说明服务于哪个后续目标，不能无限连续使用；
- `redundant`：语义重复且没有新功能；
- `related_nonadvancing`：内容相关，但无法说明对当前论证目标的贡献；
- `uncertain`：关系或贡献暂时无法可靠判断，需要保守处理。

## 6. 生成中控制

### 6.1 Claim Gate：关系有效性准入

在写出新的关键推论或解释性判断前检查：

1. 新命题是否声称由前文推出、被前文证明、由前文造成，或与前文形成确定意义关系？若否，不强行建立推导。
2. 能否指出非循环的 W，且 W 来自允许材料或可靠常识？
3. 是否遗漏关键条件，或把可能性写成必然性？
4. 选择动作：

```text
WRITE：依据足够，按规划生成。
QUALIFY：只有部分支持，降低确定性或缩小范围。
RELINK：命题各自成立但推导不成立，改为并列、对比或主观联想。
HOLD：重要依据待核实，暂不写成确定结论。
DROP：没有可用依据且不影响核心论点，删除连接或命题。
```

一个 `plausible_but_unverified` 的中间结论不能作为已确立事实继续级联推导；若后续仍依赖它，必须持续保留假设条件和不确定性。

### 6.2 Progression Gate：论证贡献准入

在 Claim Gate 之后检查：

1. 新命题或段落服务哪个尚未完成的目标？
2. 它提供哪一种贡献，具体改变了哪个待回答问题？
3. 是否只是换词重复、追加同类描述，或增加与结论无关的细节？
4. 如果属于铺垫，它为哪个后续推论提供必要条件？
5. 当前目标是否已经满足完成条件；如果没有，下一步真正缺少的是机制、证据、限定还是整合？

处理动作：

```text
ACCEPT：关系有效且具有真实论证贡献。
ACCEPT_CONTEXT：必要背景，明确依附后续目标，但不视为目标已经完成。
REDIRECT：内容相关但不推进，转去回答当前未解决的问题。
MERGE_OR_DROP：同义重复或信息重复，合并或删除。
REVIEW：关系或贡献不确定，进行保守复核。
```

`completed_goals` 只能依据实际正文是否满足完成条件来更新，不能因为生成器自称“已经论证”就标记完成。允许非线性叙述，但仍需追踪目标依赖。

连续两次候选内容被标记为 `related_nonadvancing` 或 `redundant` 时，停止沿同一方向扩写，执行一次 `REDIRECT`：补充当前缺失的机制、证据或限定；无法获得所需事实时，收窄结论或保留待核实项，不得编造内容凑齐论证。

“连续两次”只是 MVP 的可配置默认值，尚未经过实验验证。

### 6.3 最小化追问

`REVIEW` 不自动等于向用户提问。

- 如果不确定性会实质改变核心论点、文章方向或结论，只提出一个最关键的问题并等待回答。
- 如果不确定性只影响局部例子、措辞或次要展开，采用保守解释、限定表达或省略该内容，继续完成创作。
- 不因为缺少理想证据就频繁中断独立创作。

## 7. 内部控制与终稿边界

`argument_goals`、依赖关系、完成条件、命题 ID、关系标签、支持等级、Claim Gate、Progression Gate 和 relation log 都属于内部构思与校验状态。

1. 终稿不展示内部标签、任务清单、完成条件或论证地图。
2. 终稿不必按照 `argument_goals` 的顺序分段，也不必显式说明每一段完成了什么任务。
3. 允许合理的非线性叙述、节奏变化、场景描写和必要铺垫，只要它们最终服务于文章目标。
4. 不为了显得逻辑清楚，把文章强制改成“首先、其次、最后”的分析报告。
5. 关系图只保证必要连接能够被读者恢复，不要求把所有 W 都解释成显式论证句。

### 7.1 反例和反方观点的使用

内部发现的反例、反方论证和边界情况，默认只用于：

- 修正结论的范围；
- 明确成立条件；
- 避免过强表达；
- 选择更可靠的支持路径。

它们默认不作为正反辩论、异议段落或防御性澄清进入终稿。

只有以下条件之一成立时，才在终稿中展示反方内容：

1. 用户明确要求辩论、正反分析或回应异议；
2. 该反例是理解核心论点成立范围不可缺少的信息，并且可以在不歪曲用户立场的情况下自然呈现。

用户仅要求“围绕论点探讨或创作”时，不视为要求展示反方。需要体现边界时，优先用肯定方式直接说明条件和适用范围，不先构造用户没有提出的极端命题再否定。

## 8. 生成后双重审计

Validator 从实际正文重新抽取命题关系和段落功能，不照抄 Composer 自报的标签。

### 8.1 Validity Audit

对关键关系检查：

- `relation_fit`：文本实际表达的关系是否与计划一致；
- `warrant_presence`：是否存在真正的中间依据；
- `support_sufficiency`：依据是否足以支撑当前结论强度；
- `condition_coverage`：关键条件、范围和不确定性是否得到处理；
- `cascade_risk`：是否把未验证结论作为后续事实继续推导。

### 8.2 Progress Audit

对每个段落检查：

- 它实际服务哪个论证目标；
- 它提供什么贡献；
- 是否只是重复、相关但不推进或无目标铺陈；
- 必要铺垫是否真正被后文使用；
- 哪些关键问题仍未回答。

全文至少记录：

```text
goal_completion
redundancy_spans
nonadvancing_spans
unresolved_questions
validity_findings
progression_findings
```

不得用连接词数量、句数比例或模型自己的总分代替实际关系检查。

## 9. 局部修复

### 9.1 关系断裂修复动作

1. `ADD_WARRANT`：存在可验证的真实依据，但正文遗漏；
2. `QUALIFY`：支持有限，缩小范围或降低断言强度；
3. `RELINK`：改成真实的并列、对比或主观联想；
4. `DROP`：无法支持且并非必要，删除无效连接；
5. `FLAG`：依赖缺失的外部证据，且无法安全修复，保留为待核实事项。

### 9.2 推进断裂修复动作

1. `REDIRECT`：转向尚未完成的论证任务；
2. `MERGE_OR_DROP`：合并或删除重复、无贡献内容；
3. 如果缺少事实，缩小结论或保留待核实项，不得制造证据完成任务；
4. 保留真正必要的背景、铺垫、节奏和修辞功能。

所有修复遵守最小改动原则：不重写无问题段落，不改变用户核心立场，不加入未授权事实，不用冗长解释破坏原有节奏。

修复后同时重新运行 Claim Gate 和 Progression Gate；新增内容必须既有合理依据，也确实推进当前目标。默认最多修复与复验两轮，避免无限重写。

## 10. 测试矩阵

### 10.1 关系有效性

| ID | 输入关系 | 预期 |
|---|---|---|
| T01 | 销量上升 → 忠诚度提高 | 识别缺失依据，限定或标记 |
| T02 | 使用时长增加 → 满意度提高 | 不允许直接因果断言 |
| T03 | A、B 语义相近但无因果 | RELINK 或 DROP |
| T04 | 明确可靠机制支持 A→B | WRITE，不额外冗述 |
| T05 | A→B→C 中 B 未验证 | 阻断确定性级联 |
| T06 | 文学或乐评中的个人联想 | 保留为主观体验 |
| T07 | 没有“因此”但隐含因果 | 仍能识别 |
| T08 | 使用“因此”且关系有效 | 不因连接词本身误报 |
| T09 | 需要外部证据但不可获得 | FLAG，不编造证据 |
| T10 | 修复可能破坏语气 | 优先最小改动 |

### 10.2 论证推进

| ID | 输入缺陷 | 预期 |
|---|---|---|
| P01 | 连续描述“AI应用广泛”，不解释效率机制 | 检出停滞并重定向至机制 |
| P02 | 换词重复同一结论 | 标记 redundant，合并或删除 |
| P03 | 增加多个不同但无关紧要的案例 | 不把信息增加误判为推进 |
| P04 | 有效解释机制，但没有使用连接词 | 判定为有效推进 |
| P05 | 具体证据补足缺失前提 | 判定 evidence_increment |
| P06 | 合理边界收窄过强结论 | 判定 boundary_increment |
| P07 | 必要背景为后续推论铺垫 | ACCEPT_CONTEXT，不误删 |
| P08 | 文学评论的联想具有观察基础 | 允许有边界的解释 |
| P09 | 关系正确，但整段偏离当前目标 | Claim Gate 通过，Progression Gate 不通过 |
| P10 | 多段分别合理，但核心问题始终未回答 | 标记目标未完成 |

测试必须使用人工标注的正例、反例和边界例，记录原文跨度、关系类型、缺陷类型、允许修复动作、误报、漏报以及修复对逻辑和风格的影响。不能只凭模型对自身输出的评分宣称完成。

## 11. 当前完成标准

- 能分别报告 `logical_validity` 与 `argumentative_progression`，不合并成不透明总分；
- 能阻止无依据的确定性连接，或在成稿后准确定位并局部修复；
- 能识别“有效但不推进”的内容；
- 不把必要铺垫、主观解释和合理修辞一律删除；
- 不因材料不足而编造 W、证据或机制；
- 不擅自改变用户核心立场；
- 内部控制标签不进入终稿；
- 缺少关键信息时遵守最小化追问；
- 至少覆盖 T01–T10 与 P01–P10，并保留失败样本和未解决问题。

## 12. 已知未解决风险

以下两项本轮按用户选择暂未修改，需要在后续真实生成测试中重点观察：

1. Claim Gate 中“可靠常识”的允许范围仍较宽，可能让未经验证的直觉被当作 W。
2. 修复动作仍将 `ADD_WARRANT` 列在首位；需要测试它是否会诱导模型为了保留原结论而补造机制或证据。

在上述风险得到验证前，本文件只能视为候选规则，不能宣称逻辑断裂机制已经有效或达到发布标准。

## 13. 初步对照测试结果

测试记录位于 `evals/logic-break/`。本轮使用相同任务分别生成无规则基线与加载本文件后的文本，并对加载规则后的文本进行独立上下文审计。

| 案例 | 覆盖重点 | 基线 | 加载规则后 | 隔离审计 |
|---|---|---|---|---|
| LB-B01 | 使用时长、付费上升 → 满意度提高 | 失败：补造推荐匹配机制，并把代理指标用于支持满意度结论 | 通过：改为待验证解释，列出替代原因与成立条件 | 通过 |
| LB-B02 | AI → 少加班 → 高效率 → 满意 → 忠诚 | 通过：模型自行阻断确定性级联 | 通过：保持阻断，没有发生规则加载后的退化 | 通过 |
| LB-B03 | 主题相关但可能不推进 | 通过：段落已有实质推进 | 通过：保留机制、边界和整合，不误删必要内容 | 通过 |
| LB-B04 | 乐评中的主观联想 | 通过：主观归属清楚 | 通过：保留有观察基础的解释性修辞 | 通过 |

本轮只能支持以下有限结论：规则在一个明确的关系断裂失败样本上改善了输出，并在三个正例或边界例上未观察到退化。样本量为每类一次生成，尚未覆盖 T01–T10、P01–P10，也没有完成人工盲审、重复采样和误报/漏报统计，因此不构成完整验证或发布依据。
